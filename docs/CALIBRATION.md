# Калибровка: откуда взялись пороги

Все цифры получены на реальных рабочих звонках (Zoom, Teams, Webex), записанных двумя
дорожками: микрофон пользователя и системный звук. Mac на Apple Silicon, 24 ГБ.

## Распознавание узбекского

Сравнивались три модели на одном звонке с несколькими минутами узбекской речи:

| Модель | Результат |
|---|---|
| `islomov/rubaistt_v2_medium` | лучшая: связный текст, русские вставки сохраняются |
| BuzzASR (large-v3) | хуже; в fp16 на MPS выдаёт "!!!!", нужен float32 |
| `whisper-aisha-uz.v2` | хуже, устаревший generation_config |

Whisper large-v3-turbo для узбекского: язык определяется как en/fa/ru, вероятность uz около
нуля, на длинных кусках зацикливается.

Пороги отбора окон для второй модели (`uzbek.py`):

| Параметр | Значение | Почему |
|---|---|---|
| `RU_MAX` | 0.5 | Whisper не говорит "uz", поэтому вопрос "не русский ли это" |
| `EN_SURE` | 0.6 | явный английский в узбекскую модель не отдаётся: она пишет его "узбекскими" словами, и проверка текста это пропускает |
| `PIECE_SEC` | 12 | модель не даёт меток времени внутри окна; на кусках длиннее ~30 с зацикливается |
| `UZ_MIN_LOGPROB` | -0.9 | ниже - шум, музыка, клавиатура |
| `UZ_MIN_WORDS` | 4 | "mhm. xo'p." на шуме клавиатуры - не речь |
| `UZ_STICKY_SEC` (live) | 90 | в коротком живом окне узбекский с русскими заимствованиями проходит за русский; после узбекской реплики вторая модель пробуется первой |

Маркеры `-da/-ga/-ni` из проверки текста убраны: ими кончаются и русские слова, записанные
латиницей ("i togda bolshe vopros netu" проходило как узбекский).

## Живые субтитры: задержки

Встреча из двух дорожек (звонок + микрофон, звонок из динамиков, есть узбекский кусок)
проигрывалась в реальном времени. M4, 24 ГБ, whisper-large-v3-turbo, перевод gemma4:12b-mlx в
Ollama с `num_ctx=4096`.

| | 5 мин | 10 мин |
|---|---|---|
| звонок: текст на экране после начала фразы, медиана / p90 | 1.44 / 4.6 с | 1.07 / 3.2 с |
| звонок: финал после конца фразы, медиана / p90 | 3.0 / 6.0 с | 3.6 / 6.9 с |
| перевод узбекского после конца фразы, медиана / p90 | 3.8 / 5.4 с | - |
| проход черновика / финала (среднее) | - | 0.38 / 1.1 с (p95 3.7) |
| GPU занят | 35% | 54% |
| память MLX | - | ровно 3.15 ГБ все 10 минут |

- Прежняя схема (окна 6-20 с по паузе, без черновиков): текст через 1-6 с после конца фразы.
  Финал новой схемы на быстром собеседнике по p90 даже хуже (6-7 с против 4.5 с), но первый
  текст виден через ~1 с за счёт черновика.
- Порог паузы: 0.6 с, пока буфер короче 5 с; 0.35 с до 8 с; потом 0.25 с; в 8 с режется по
  самой тихой точке. С фиксированными 0.6 с у беглого собеседника буфер рос до 8 с постоянно.
- Черновик без меток слов: 0.42 с на 15 с звука против 0.77 с с ними.
- Финал своей речи на микрофоне (черновика нет): 4.6-5.7 с.
- Перевод через OpenAI-совместимый `/v1` у модели с рассуждениями - 10-30 с на реплику.

## Чему верить: пороги `unsure`

`avg_logprob < -0.8`, `no_speech_prob > 0.4`, `compression_ratio > 2.0`, больше 5 слов/с;
иностранная строка с p(lang) ниже 0.5. На 10 минутах звонка: 5 из 125 строк помечены
(португальский и французский мусор, две слишком быстрые фразы), выдуманных строк без пометки не
было. Сам Whisper как детектор галлюцинаций слаб (F1 ~24% по публикациям), поэтому сигналы не
заменяют VAD перед распознаванием, а дополняют его.

## Эхо звонка на микрофоне

Без наушников микрофон слышит звонок из динамиков. Whisper на этом эхе выдаёт
"I'm going to go to the next video", японские титры, иврит. Лаг ищется по корреляции
логарифмических огибающих двух дорожек (`audio.crosstalk_lag`, порог 0.15). Куски микрофона,
огибающая которых повторяет звонок (`drop_crosstalk`, порог 0.45 на окнах 2 с), вырезаются.
Когда пользователь говорит поверх звонка, огибающие расходятся, и такая речь остаётся. В live
режиме лаг считается по последним 60 с, работает после 5 с записи. До этого на микрофоне
допускаются только `ru/en`.

## Голоса: отпечатки и порог совпадения

Отпечаток - эмбеддинг NeMo titanet_small (sherpa-onnx, CPU), средний по <= 12 самым длинным
чистым репликам метки, взвешенный по длительности. Реплика длиннее 10 с режется до середины:
на минутных кусках модель падает.

Измерения (косинусное сходство):

| Пара | Сходство |
|---|---|
| один человек, две половины одной встречи, чистые реплики | 0.92-0.98 |
| один человек (свой микрофон) в разных встречах | 0.64-0.88 (медиана 0.70) |
| разные люди, чистые реплики | 0.19-0.26 |
| разные люди, в отпечаток попали реплики на одновременной речи | 0.69 |
| разные люди между встречами, худший случай | 0.52 |

Отсюда:

- `MATCH = 0.62` - ниже нижней границы "свой между встречами" с запасом от худшего чужого;
- `MARGIN = 0.08` - если два голоса библиотеки почти одинаково похожи, имя не даётся никому;
- `OTHER_QUIET_DB = 12`, `LOUD_DB = 10` - в отпечаток идут только реплики, где своя дорожка
  на уровне речи, а все остальные минимум на 12 дБ тише своей речи. Без этого фильтра
  микрофон смешивает человека с эхом звонка, и разные люди дают 0.69;
- `MIN_PRINT_SEC = 8` - меньше чистой речи даёт отпечаток, похожий на всех.

Проверка на 6 старых встречах после обучения на одной: голос пользователя узнан во всех 6
(0.76-0.88), чужой голос не получил имя ни разу (максимум 0.52).

## Скрипт: матрица сходства для своих данных

```python
import json
import subprocess
from pathlib import Path

import numpy as np
from meetvoice.voices import embedder, speaker_prints


def load(path):
    raw = subprocess.run(["ffmpeg", "-v", "error", "-i", str(path), "-ac", "1", "-ar", "16000",
                          "-f", "f32le", "-"], capture_output=True, check=True).stdout
    return np.frombuffer(raw, dtype="<f4").copy()


embed = embedder(Path.home() / ".cache" / "meetvoice")
prints = {}
for meeting in ["m1", "m2", "m3"]:                      # папки: mic.wav, call.wav, lines.json
    d = Path("meetings") / meeting
    audio = {"mic": load(d / "mic.wav"), "call": load(d / "call.wav")}
    lines = json.loads((d / "lines.json").read_text())
    # половины одного человека: внутривстречная стабильность
    for name in {s["speaker"] for s in lines}:
        mine = sorted((s for s in lines if s["speaker"] == name), key=lambda s: s["start"])
        lines += [dict(s, speaker=name + " #A") for s in mine[0::2]]
        lines += [dict(s, speaker=name + " #B") for s in mine[1::2]]
    for label, (vec, sec) in speaker_prints(audio, lines, embed).items():
        prints[f"{meeting}:{label}"] = vec

keys = sorted(prints)
for k in keys:
    print(f"{k:<28}", " ".join(f"{float(prints[k] @ prints[o]):.2f}" for o in keys))
```
