# Инструкция для агента: встроить meetvoice в систему

Документ написан для AI-агента (Claude Opus или аналог), которому поручили подключить этот
модуль к существующей системе записи или проведения встреч. Человек, поставивший задачу, знает
свою систему, но не знает этот модуль. Работай по шагам, на каждом шаге проверяй результат.

## Что даёт модуль

1. **Живые субтитры с переводом.** Растущий звук двух дорожек (микрофон пользователя и звук
   звонка) режется на окна по паузам. Окна распознаются, реплики на иностранном языке
   переводятся локальной LLM. Задержка на живом звонке: текст через 3-6 с после фразы, перевод
   ещё через 1-2 с.
2. **Второй язык, который Whisper не знает.** Сейчас это узбекский. Whisper large-v3-turbo
   узбекский не опознаёт (говорит en/fa/ru) и зацикливается на нём. Модуль сам находит такие
   окна, распознаёт их дообученной моделью и проверяет, что вышел узбекский текст. Схема
   переносится на любой подобный язык (см. "Другой язык" ниже).
3. **Окно-оверлей.** Страница с режимами "оба / перевод / оригинал" и протокол опроса
   `/live?after=N`. На macOS дополнительно есть нативная полупрозрачная панель поверх всех
   окон, невидимая для демонстрации экрана.
4. **Библиотека голосов.** Отпечатки голосов названных спикеров сохраняются. В следующих
   встречах безымянные метки диаризации ("Speaker 1", "Я") получают имена сами, если голос
   совпал уверенно.

Чего модуль НЕ делает: не захватывает звук, не делает диаризацию, не хранит встречи. Это
остаётся на стороне системы. Модуль получает звук и готовые реплики.

## Шаг 0. Разберись в системе, прежде чем писать код

Найди в кодовой базе ответы и выпиши их человеку одним сообщением:

- **Платформа инференса.** Модуль проверен только на Apple Silicon (mlx-whisper). Если система
  работает на Linux/CUDA, нужен адаптер (шаг 2.3); скажи об этом сразу.
- **Как приходит звук.** Варианты: (а) растущие WAV-файлы на диске; (б) колбэки с PCM-кусками
  (SDK захвата, WebRTC, сокет); (в) только готовые файлы после встречи. Для (в) живые субтитры
  не нужны, бери только библиотеку голосов (шаг 5).
- **Сколько дорожек.** Две раздельные (микрофон + звонок) дают фильтр эха и чистые отпечатки
  голосов. Одна смешанная тоже работает, но хуже. Спроси, можно ли писать раздельно.
- **Есть ли диаризация** и какой формат реплик: нужен список `{start, end, speaker, text}` в
  секундах от начала записи.
- **Где показывать субтитры:** веб-интерфейс системы, отдельное окно, нативный клиент.
- **Какая LLM доступна для перевода:** Ollama, LM Studio, vLLM, облачный шлюз. Модель и URL.
- **Родной язык пользователей** (`native`, по умолчанию `ru`). Всё остальное считается
  иностранным и переводится.

Не начинай интеграцию, пока не ясны платформа и способ получения звука.

## Шаг 1. Установка и самопроверка

```bash
python3.12 -m venv .venv
.venv/bin/pip install ".[dev]"
.venv/bin/pytest -q          # 16 тестов, без моделей и сети
.venv/bin/pip install ".[mlx,voices]"    # на Apple Silicon
```

Тесты должны пройти до любых изменений. Затем прогони живой пример на любой записи разговора,
где есть иностранная речь:

```bash
.venv/bin/python examples/live_from_wav.py call.m4a --llm-model <модель из Ollama>
```

Пример проигрывает файл как живой звонок в реальном времени и печатает строки с задержкой от
старта. Страница оверлея: http://127.0.0.1:8765/. Первая загрузка узбекской модели (~1.5 ГБ)
и конвертация займут несколько минут, дальше она берётся из `--models-dir`.

Ожидаемо: узбекские строки помечены `uz` и переведены, английские помечены `en` и переведены,
русские не переводятся. Перевод отстаёт от текста на 1-2 с. Если отставание 10-30 с,
см. шаг 3.

## Шаг 2. Подключить живые субтитры

Точка входа: `meetvoice.live.LiveTranscriber`.

```python
from functools import partial
from pathlib import Path

from meetvoice import asr, uzbek
from meetvoice.live import LiveTranscriber, Track
from meetvoice.translate import Translator

uz_path = uzbek.model_path(Path("/var/lib/app/models"))   # один раз, при старте приложения
live = LiveTranscriber(
    tracks=[Track(Path(rec_dir) / "system.wav", "Собеседник"),
            Track(Path(rec_dir) / "mic.wav", "Я", mic=True)],
    transcriber=asr.transcribe_window,
    uz_finder=partial(uzbek.live_find, uz_path),     # None, если второй язык не нужен
    translator=Translator("http://127.0.0.1:11434", "gemma3:12b", kind="ollama"),
    native="ru", foreign_to="ru", translate_to="",
    out_path=Path(rec_dir) / "live.jsonl",            # черновик на диск, необязательно
)
live.start()      # при старте записи
...
live.stop()       # при остановке; flush=True дораспознает хвост буфера
```

### 2.1 Звук приходит файлами

Подходит, если захват пишет WAV и дописывает его по ходу записи (заголовок может быть не
финализирован до стопа). `Track(path=..., ...)`. Поддерживаются PCM16 и float32, любые
частота и число каналов.

### 2.2 Звук приходит колбэками

```python
from meetvoice.live import PushSource, Track

call_src = PushSource(rate=48000)
mic_src = PushSource(rate=48000)
tracks = [Track(None, "Собеседник", source=call_src), Track(None, "Я", mic=True, source=mic_src)]
# в колбэке SDK захвата, из любого потока:
call_src.push(pcm_float32_chunk)       # mono или (n, channels); int16 сначала / 32768
```

Обе дорожки должны начинаться в один момент: время реплик считается от первого сэмпла, и по
нему фильтр эха сопоставляет микрофон со звонком.

### 2.3 Не Apple Silicon

`transcriber` - любая функция `audio(16 kHz mono float32) -> [{start, end, text, lang}]`.
Для CUDA, например, faster-whisper (НЕ проверено в этом репо, проверь сам):

```python
from faster_whisper import WhisperModel
model = WhisperModel("large-v3-turbo", device="cuda", compute_type="float16")

def transcriber(audio):
    segs, info = model.transcribe(audio, vad_filter=False, condition_on_previous_text=False,
                                  temperature=0.0, no_speech_threshold=0.5)
    out = [{"start": s.start, "end": s.end, "text": s.text.strip(), "lang": info.language} for s in segs]
    return asr.clean_segments([s for s in out if s["text"]])
```

Фильтры из `asr.transcribe_window` (галлюцинации, повторы, чужие алфавиты, метки времени за
концом окна) перенеси в адаптер обязательно, иначе на тишине и эхе пойдёт мусор.

Узбекский путь (`uzbek.py`) завязан на mlx. Для CUDA загрузи ту же модель
`islomov/rubaistt_v2_medium` через transformers или конвертируй в CTranslate2 и повтори
логику `live_find`: проверка языка Whisper -> декодирование кусками по 12 с с temperature 0 ->
`is_uzbek` -> отбросить, если не узбекский. Функции `tidy`, `is_uzbek`, `_looped`, `_pieces`
от mlx не зависят, бери их как есть.

### 2.4 Правила, которые нельзя нарушать

- Все вызовы моделей идут через `asr.LOCK`. Один GPU, один декодер. Если в системе есть своя
  пакетная транскрибация на той же модели, она тоже должна брать `asr.LOCK`, иначе две
  транскрибации будут воевать за кэш модели mlx-whisper.
- Узбекская модель держится отдельно и подменяется в кэш mlx-whisper только на время вызова
  (`asr.use_model`). Не вызывай `mlx_whisper.transcribe` с путём узбекской модели напрямую:
  кэш переключится, и каждое окно будет перезагружать 1.5 ГБ весов.
- Перед загрузкой большой локальной LLM в ту же память вызови `uzbek.release()` и сбрось кэш
  mlx-whisper, иначе Metal OOM на 24 ГБ.
- `condition_on_previous_text` всегда False.

## Шаг 3. Перевод

- Для Ollama используй `kind="ollama"`: родной `/api/chat` с `think: false`. Через
  OpenAI-совместимый `/v1` модель с рассуждениями (gemma4, qwen3) думает перед каждой репликой:
  10-30 с вместо 1-2 с, и перевод безнадёжно отстаёт. Это главная причина "медленного перевода".
- Для LM Studio, vLLM, шлюзов: `kind="openai"`, серверные переключатели рассуждений передай
  через `extra={...}`.
- Прогрей модель одним вызовом при старте записи, иначе первые переводы опоздают на время
  загрузки модели (~30 с).
- Переводчику уходят 4 предыдущие реплики как контекст: фрагменты распознавания переводятся по
  смыслу. Для иностранной речи промпт говорит, что текст получен распознаванием; фразу "если уже
  на этом языке, верни как есть" в этом случае не добавляй: неуверенная модель возвращала
  узбекский текст без перевода.
- Иностранные реплики (язык не равен `native`) переводятся на `foreign_to` всегда. Остальные -
  только если пользователь включил `translate_to`.

## Шаг 4. Показать субтитры

Контракт опроса один для всех вариантов:

```
GET /live?after=N  ->  {"active": true, "session_id": "...", "error": null,
                        "entries": [{"i", "start", "end", "speaker", "text", "lang",
                                     "target", "translation"?, "translated_to"?}]}
```

Клиент запрашивает `after = индекс первой строки без пришедшего перевода` (у которой `target`
не пуст, а `translation` ещё нет). Так строки с отстающим переводом перезапрашиваются, пока он
не придёт. Готовая реализация такого клиента: `src/meetvoice/static/overlay.html`.

Варианты подключения:

1. **В веб-сервере системы** (предпочтительно): отдать `overlay.html` и `/live` своим
   фреймворком. Пример для FastAPI:

   ```python
   @app.get("/live")
   def live_entries(after: int = 0):
       live = recorder.live          # текущий LiveTranscriber или None
       if not live:
           return {"active": False, "entries": []}
       return {"active": True, "session_id": recorder.session_id,
               "entries": live.since(max(after, 0)), "error": live.error}
   ```

   Путь в `fetch` у страницы относительный (`live?after=`), поэтому страница работает под любым
   префиксом. Если у системы есть авторизация, закрой оба маршрута ею: это содержимое встречи.
2. **Отдельно:** `meetvoice.server.serve(get_live)` поднимает stdlib-сервер на 127.0.0.1.
3. **macOS-панель:** `meetvoice.macos_overlay.Overlay(url).show()` в главном потоке
   приложения с NSApplication (rumps, PyObjC) или `run_standalone(url)` отдельным процессом.
   Панель не забирает фокус, видна поверх полноэкранного Zoom и на всех рабочих столах, в
   демонстрацию экрана не попадает (`sharingType = none`).
4. **Свой UI:** опрашивай `live.since(after)` напрямую по тому же правилу.

## Шаг 5. Библиотека голосов

Когда вызывать:

1. **После диаризации и других способов назвать спикеров** (имена с экрана, из календаря,
   ручные): `VoiceLibrary.apply(meeting_id, audio, segments, embed)`. Метод переименует только
   общие метки (`is_generic`: "Я", "Speaker 1", "Собеседник 2" и т.п.) и сразу запомнит
   отпечатки уже названных спикеров этой встречи.
2. **Когда пользователь переименовал спикера** в интерфейсе: пересчитай
   `speaker_prints(audio, segments, embed)` с новыми именами и вызови
   `remember(meeting_id, prints)` в фоне (это занимает секунды). Вклад этой встречи заменяется
   целиком, поэтому исправление опечатки в имени не оставляет "призрака".
3. **Интерфейс управления:** список (`load()`), `rename`, `forget`. Без возможности забыть голос
   функцию не включай.

```python
from pathlib import Path
from meetvoice.voices import VoiceLibrary, embedder

lib = VoiceLibrary(Path("/var/lib/app/voices.json"))
embed = embedder(Path("/var/lib/app/models"))        # ~40 MB, CPU, грузится один раз
audio = {"mic": mic_16k_float32, "call": call_16k_float32}
found = lib.apply(meeting_id, audio, segments, embed)  # segments переименованы на месте
# found = {"Speaker 1": ("Anna", 0.81)}  -> покажи пользователю "узнан по голосу, сходство 0.81"
```

`audio` - словарь дорожек. Названия дорожек любые. Метка спикера сама определит, на какой
дорожке она живёт.

Обязательно покажи пользователю, кто назван по голосу и с каким сходством, и дай исправить:
ошибка распознавания голоса не должна молча попасть в протокол.

**Юридически:** отпечаток голоса - биометрические персональные данные. Хранить локально, не
отправлять наружу, иметь согласие участников по правилам организации, давать удалять. Скажи об
этом человеку, который ставит задачу, до включения функции.

## Шаг 6. Откалибровать пороги на данных системы

Пороги в `voices.py` и `uzbek.py` подобраны на нескольких реальных встречах (см.
`docs/CALIBRATION.md`). Микрофоны, кодеки и языки другой системы могут их сдвинуть. Проверь
на 5-10 встречах:

1. Возьми встречи, где один и тот же человек назван правильно. Раздели его реплики на чётные и
   нечётные, построй два отпечатка: сходство внутри человека должно быть 0.9+.
2. Сходство одного человека между разными встречами (норма 0.64-0.88) и разных людей между
   собой (норма 0.2-0.5). Поставь `MATCH` посередине зазора, `MARGIN` оставь 0.08.
3. Если "свой-свой" ниже 0.6, проверь, что отпечатки строятся из чистых реплик: две раздельные
   дорожки, `OTHER_QUIET_DB` работает. Смешанные отпечатки давали 0.69 между разными людьми.

Скрипт для матрицы сходства - в `docs/CALIBRATION.md`.

## Чек-лист приёмки

- [ ] `pytest` зелёный, в том числе после твоих правок
- [ ] Живой пример на записи системы: иностранные строки переводятся, русские нет, перевод
      отстаёт от текста не больше 2-3 с
- [ ] На записи без наушников (звук звонка из динамиков) на микрофоне нет строк-эха
      ("I'm going to go to the next video", японские титры)
- [ ] Окно субтитров открывается в целевом интерфейсе, режимы переключаются
- [ ] Библиотека голосов: голос, названный в одной встрече, узнаётся в другой; чужой голос не
      получает имя; пользователь видит сходство и может исправить или забыть голос
- [ ] Пороги проверены на данных системы (шаг 6), цифры записаны
- [ ] Субтитры и голоса не уходят наружу без ведома пользователя

## Другой язык вместо узбекского

1. Найди дообученную модель Whisper для языка (Hugging Face, формат transformers).
2. `uzbek.MODEL_REPO`, код языка в `_decode` (`language="uz"`), словарь частых слов и
   морфологические маркеры в `is_uzbek` замени на свои.
3. Проверь, что Whisper turbo действительно не опознаёт язык: если опознаёт уверенно, второй путь
   не нужен, достаточно обычного Whisper с `language=None`.
4. Пороги `RU_MAX` и `EN_SURE` перепроверь: они задают, какие окна вообще отдавать второй модели.
